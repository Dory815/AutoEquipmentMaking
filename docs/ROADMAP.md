# 实施计划与发布门槛

> 2026-10-24 版本调整：旧 v1.0 对应 Alpha 1.0；加入村民交易、尚未加速交易的 RC.5 对应 Alpha 1.2；旧 v1.1 的 RC.6 对应 Alpha 1.3。原 v1.2 仓库物流计划取消，下面的 v1.2 内容仅为历史设计，不属于开发承诺。当前正式版为 1.0，包含设置界面、导航、跳跃提升与自动疾跑。版本和验证范围以 [发布记录](RELEASES.md) 为准。

日期：2026-10-23。当前阶段：规划与空框架。此计划不表示功能已经实现。

## 分阶段计划

| 阶段 | 工作 | 依赖 | 交付与通过条件 |
|---|---|---|---|
| M0 环境探针 | Servux 0.11.2 握手、共存、单箱读取；规则与菜单费用基线 | 配置权限、目标服务器、可用站位 | 读取已知箱；读目标书组件；一次合成/锻造/附魔实际确认；记录 Carpet 规则和依赖锁 |
| M1 规划内核 | 清单模型、材料预算、库存分配、精确合并树搜索 | M0 确认规则 | 所有装备与独立穷举一致；不同惩罚库存全盒分配无重复、总费用最小 |
| M2 取物与移动 | 区域扫描、位置选择、容器槽位事务、输入隔离 | M0 协议，M1 契约 | 乱放且受遮挡的潜影盒取物；外部改动和网络延迟不误取 |
| M3 制作流水线 | 工作台、锻造台、铁砧、经验预算、备用铁砧 | M1、M2 | 各类装备逐件完成；费用一致；缺货分类和通知去重 |
| M4 装箱和恢复 | 空盒放置、逐件核验、回收、交付、断线对账 | M3 | 连续 3 盒全部合格；急停、断线、满背包和铁砧损坏场景通过 |
| v1.0 发布 | 固定依赖、文档、生产日志、兼容矩阵 | M4 | PRD v1.0 全部验收通过 |
| M5 村民补书 | 报价索引、预算、补货等待、交易对账 | v1.0 | 可交易缺书自动补齐；两种不可交易书正确通知；交易规则按实际报价 |
| v1.1 发布 | 交易兼容矩阵与回归 | M5 | 不降低 v1.0 的正确性 |
| M6 仓库物流 | home 适配、到达验证、仓库扫描、六项补给 | v1.1、现场 home 配置 | 完整礼包 20 格；传送失败和缺物时保留装备盒，不重复生产 |
| v1.2 发布 | 仓库场景与完整链路回归 | M6 | PRD v1.2 全部验收通过 |

M0 是关键前置条件。先验证现有协议接入和附加包规则，再投入完整执行器。若 M0 发现 Servux 通道冲突，则先完成复用适配或菜单读取回退设计。

## 单人开发工作量估算

以下为规划估算，不是交付承诺。每个工作日按完整开发与验证投入计算。

| 范围 | 初始估算 |
|---|---|
| M0 | 2–4 工作日 |
| M1 | 3–5 工作日 |
| M2 | 5–8 工作日 |
| M3 | 4–7 工作日 |
| M4 与 v1.0 回归 | 4–6 工作日 |
| v1.1 | 4–7 工作日 |
| v1.2 | 4–7 工作日 |

v1.0 合计 18–30 工作日。主要不确定项是寻路、Servux 与已有客户端共存、网络下槽位对账、服务器自定义规则。M0 完成后重新估算。

## 范围控制

- v1.0 不同时开发 Carpet 服务端执行器。
- v1.0 不扩展到任意复杂地形、低等级拼书、多附魔书或自动获取经验。
- v1.1 不把不可交易附魔书当作能靠普通村民补齐的库存。
- v1.2 不把自动给新人派发礼包加入原有生产范围。
- 任何“最优”标签都要求精确搜索完成；求解超时不是成功。

## 实施前现场信息

场地坐标、home 命令和物资来源在对应阶段配置，不阻塞本轮文档与框架交付。用户不需要先整理原料潜影盒。容器的可交互站位仍需 M0 现场记录。
