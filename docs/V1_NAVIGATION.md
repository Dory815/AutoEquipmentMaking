# 正式版 1.0：寻路、跳跃提升与自动疾跑

日期：2026-10-24。第二项优化，沿用 `1.0.0` 开发版本。

## 实现

原导航以四方向广度搜索选择站位。它在每个节点释放前进键，瞬间转动视角，且把水平碰撞直接当作跳跃条件。新导航使用 Minecraft 26.2 原版 `PathFinder` 的 A* 搜索，配套玩家专用 `NodeEvaluator`。原版 `WalkNodeEvaluator` 提供地面高度和危险方块分类。没有生成代理生物，没有复制苦力怕的攻击或引爆逻辑。

直接读取本地 Minecraft 26.2 jar 的方法签名和字节码，核对 `PathFinder.findPath`、`NodeEvaluator`、`WalkNodeEvaluator` 与 `LivingEntity` 的跳跃公式。`PathFinder` 只把 Mob 参数传给节点评估器的 `prepare`；玩家评估器覆盖该入口，使用真实玩家，不调用默认的 Mob 初始化逻辑。

- **路线**：八方向平面移动；只有整段玩家碰撞体可通过且脚下有支撑时才合并平地节点。不得穿过墙角，不走液体、岩浆块、火、仙人掌、细雪与栅栏路径。限制工坊边界、已加载区块、世界边界和最大搜索量。
- **高度**：根据碰撞形状读取真实站立高度，处理半砖和普通台阶。上升最多两格，下降最多一格；上升路径必须满足实际跳跃高度和完整头顶净空。此项不是游泳、攀梯、开门或跨越深坑功能。
- **跳跃提升**：读取玩家当前 `JUMP_BOOST`、跳跃力量和重力，结合起跳地面的跳跃系数计算高度。信标给予跳跃提升 II 时，原版参数满足两格台阶。效果剩余时间不足 31 tick 时不采用依赖该效果的新跳跃。清空头顶的检查仍使用当前实际效果的完整跳跃弧线。客户端效果数据不区分信标与药水；相同效果使用相同物理判断。
- **移动**：同一 tick 连续消费路径点。每 tick 水平转向最多 20 度，俯仰最多 4 度。转向未对准时暂不前进。只为已确认的上升路径触发跳跃，不因碰墙持续跳跃。
- **自动疾跑**：机器人前进时持续按住原版疾跑键。兼容“按住”和“切换”两种疾跑设置；切换模式只在状态不同时触发一次切换。转向停车、到点、暂停、失败和结束时释放疾跑。遵守原版饥饿值、物品使用与碰撞规则，不修改速度属性。停止移动时立即清除本地疾跑状态。
- **原版自动跳跃**：仅在机器人控制导航期间阻止额外的自动跳跃，并清除此前排队的自动跳跃。保留用户的自动跳跃设置值，退出导航后恢复原版行为。
- **交互站位**：要求眼睛到目标的距离和射线同时合格。墙后目标即使距离足够，也先绕墙。容器、村民、铁砧补位与成品盒拾取复用此导航；打开菜单仍等待原版服务端确认。
- **变化与失败**：跳跃能力变化、前方障碍变化或连续 45 tick 无进展时重新规划。连续重算失败后停止，不反复撞墙。无完整路径时不接受原版寻路返回的部分路径。

主代码：`client/src/main/java/io/github/autoequipmentmaking/client/PlayerNavigation.java`。调用入口保留 `Robot.Navigator`，测试位于 `client/src/gametest`。

## 验证记录

所有游戏测试只在项目独立单人存档内运行。每个套件退出后立即归档日志。未启动 PCL、formal-client，未连接 201 正式服。

`docs/evidence/navigation-v1/attempt-1/`：初版 11 项导航场景通过。`attempt-2/`：加入半砖、斜角和原版自动跳跃隔离后，14 项场景通过。两个记录均早于自动疾跑修改，不能用作疾跑版本的运行证明。

最终导航套件 `final-navigation/` 的 17 项场景全部通过，客户端正常退出：

| 范围 | 结果 |
| --- | --- |
| 平地斜线、按住疾跑、切换疾跑 | 实际前进时疾跑；不改用户设置；到点关闭疾跑 |
| 隔墙箱子、偏离方块中心的容器通道 | 绕墙后打开实际箱子；通道只规划一次 |
| 一格台阶、半砖上升与下降、封闭斜角 | 实际玩家通过；半砖不额外跳跃；斜角绕行 |
| 无效果与跳跃提升 I | 拒绝不可达的两格台阶，不发送移动输入 |
| 真实四层信标的跳跃提升 II | 实际跳上两格台阶；独立服务端确认终点 |
| 两格台阶的低顶、岩浆块 | 低顶拒绝；危险地面绕行，无伤害 |
| 效果移除、新增障碍 | 效果移除后安全停止；新增墙后重算并抵达 |
| 暂停与恢复、低饥饿值 | 暂停释放移动和疾跑；恢复完成；饥饿值 6 时仍能步行，不绕过原版疾跑限制 |

平地斜线案例从 `(0.5,65,0.5)` 前往 `(10.5,65,10.5)`。同一新寻路算法，普通行走版本为 67 tick，最终疾跑版本为 52 tick，减少 22.4%；最终版本记录 50 个实际疾跑 tick。该比较仅针对这个场景，不代表整套装备制作提速 22.4%。

最终完整制作套件 `final-production/` 通过并正常退出：6 笔集中采购，实际制作、附魔、装箱并交付 14 件装备、1 盒，消耗 319 级（1500 → 1181）。初始私人 7 颗绿宝石与 3 本书保持不变，消耗 1 份食物。没有直接生成最终装备代替生产验收。

两个最终套件使用同一分发包，SHA-256 为 `df53234249c4377a09c9ef8a42c8f25f2c65cc54275f9467eeec0654dd2d3ca0`。发布检查核对 66 个主代码 class 与编译输出一致，确认游戏测试未进入 jar；9 项规划内核测试通过。证据见 `docs/evidence/navigation-v1/release-checks.json`。

中间版本的 `production/` 与 `production-diagnostic/` 制作测试失败，错误为“移动受阻，重新寻路后仍不可达”。诊断记录确认，路线合并从玩家实际位置出发，而逐 tick 校验错误地从所在方块中心出发。容器通道旁的玩家位置 `(4.123,65,6.952)` 因此重复规划同一路径。修订后平地校验与路线合并统一使用玩家实际位置，并增加 `off-center-corridor` 回归场景。失败日志保留，不计通过。

生产测试准备阶段在内存中固定完整装备清单与默认制作选项，隔离之前设置界面测试保存的选项。此处理只属于测试代码，不写用户设置文件。

## 执行方法

使用项目 JDK 25 和 `.gradle-user-home`。本次执行使用本地脚本 `.tools/run_navigation.ps1`；公开脚本 `tools/run_navigation.ps1` 接受 `navigation`、`v11-production`、`complex` 三个套件，要求独立且未使用过的证据目录名。

```powershell
& ./tools/run_navigation.ps1 -Suite navigation -EvidenceName navigation-new-run
& ./tools/run_navigation.ps1 -Suite v11-production -EvidenceName production-new-run
```

公开脚本 `tools/run_navigation.ps1` 使用 `JAVA_HOME` 中的 JDK 25，允许指定独立测试实例目录。脚本执行 `:client:jar :client:runClientGameTest`，记录分发 jar 的 SHA-256，保存本次日志、任务事件、截图和导航指标。测试源码不进入分发 jar。

同一安装包同步到 PCL 独立版本 `26.2-自动打装备`。三个配置文件和全部 81 个受保护文件哈希不变，模组数量仍为 5。旧 RC.6 备份到 `runtime/pcl-equipment-client/backups/rc6-before-v10-navigation-20261024`。安装记录见 `docs/evidence/navigation-v1/pcl-update.json`。未启动 PCL，未测试远程服务器。
