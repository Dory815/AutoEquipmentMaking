# 竖直活板门旁的寻路恢复

日期：2026-10-24。

## 现场与原因

用户报告 1.0.1 提示寻路受阻，并确认附近为竖直打开的活板门。只读任务日志显示，采购绿宝石块后前往工作台 `(1072,57,24)`，玩家在 `(1070.699999988079,57,25.699999988079)` 连续重算相同边 `(1070,57,25) → (1071,57,25)`，最终停止，报错 `移动受阻，重新寻路后仍不可达`。

原路径规划从方块中心搜索，但导航在距离当前路径点不足 0.32 格时立即跳过它。竖直活板门的薄碰撞面会使偏离中心的玩家无法斜着进入下一格。虽然从当前格中心走向下一格是安全的，从玩家实际位置直接进入却会撞到活板门边缘。重新搜索仍从同一格中心开始，又立即跳过中心，导致重复失败。

在独立单人存档放置竖直活板门，并采用与现场相同的相对偏移站位，旧代码复现四次相同重算及相同错误。没有复制或操作正式服世界；现场方块布局没有完整快照，复现使用等效薄碰撞面和已知站位。

## 修复

消费路径点前，检查玩家实际位置是否可以到达后继节点。如果中心路线仍有效，而玩家偏移位置暂时不能直接进入下一段，就保留当前路径点，让玩家先向该点靠拢。此时使用更小的停车距离，直到下一段的实际碰撞检查通过，再继续行走。

真实障碍发生变化时仍重新规划。保留玩家完整碰撞体、脚下支撑和危险方块检查。没有把竖直活板门当作空气，也没有增加自动开关活板门的动作。

代码：`PlayerNavigation.tick` 的路径点消费与停车判断，及统一的 `canApproach` 检查。
