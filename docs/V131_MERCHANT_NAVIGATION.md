# 1.3.1 矿车村民交互寻路修复

## 故障与原因

1.3 在采购阶段对矿车村民报告“没有安全路线”。交易入口复用了方块容器的终点，把村民脚部所在方块的中心作为交互目标；矿车中的实体脚部低于地面，方块中心不适合作为目标。仅改成眼部仍失败：告示牌的选取框又使原有 OUTLINE 视线误判遮挡。

另一次外部库存输入触发保护；原记录没有具体输入来源。这个保护继续保留。

## 修复

交易导航绑定村民 UUID，以实时实体边界盒和多个身体采样点寻找可交互位置。使用 COLLIDER 视线消除无碰撞告示牌选取框的误判，仍遵守墙、半砖和活板门的实际碰撞。交互前重新确认目标与可见点，等待实际服务端交易菜单后才购买。容器导航和库存保护规则继续保留。

仅眼部目标和多点 OUTLINE 两个中间方案均失败；最终方案在同一原始场景验证。

## 验证

- 修复前的 1.3 原始字节码在独立基准副本复现故障。
- 1.3.1 从三个原始故障起点实际打开对应矿车村民的交易菜单，村民 UUID、乘坐关系、报价使用次数及 298 个活板门保持。
- 独立单人采购回归完成 4 笔，覆盖同级村民轮换与真实 20 秒冷却。10 项引擎测试通过。78 个客户端 class、7 个内嵌引擎 class 与运行及编译输出一致，分发 jar 不含游戏测试。
- 经用户单独授权，1.3.1 正式服新人装备同一任务交付 2 盒/28 件，完成 40 笔采购，消耗 228 绿宝石及 570 级。两个成品盒均通过数量、附魔和耐久检查；交付箱其余原槽完整物品组件保持。
- 两次自然补货后继续采购，合计 64 次 20 秒复查。三次界面暂停及一次补经验 good 门禁后均继续同一任务，最终队列为空。没有取消重开、清除未确认保护或直接生成成品。
- 正式服两盒均复用 11 件下界合金底材。本轮未验证正式服批量工具、多名耐久 III 村民轮换、砂轮或新制底材。没有采集服务端 MSPT/TPS，性能问题仍未确认。
- 用户随后确认实际测试没有问题并授权发布。

任务暂停恢复保留的是当前进程内的队列，不代表关闭游戏后的自动续作。初始食物自动进食一次，有对应任务记录；不能声称测试结束时全部初始物品数量不变。
