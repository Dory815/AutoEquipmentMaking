## 验证证据格式

每次运行记录游戏/Fabric/Servux/Carpet 版本、规则快照、种子或测试场景标识、任务日志和构建 SHA256。日志列出输入、输出、费用与异常，不要求录像才能判断基本正确性。

开发用独立基准不得直接复用被测规划器的状态转移逻辑，否则不能证明最优性。支持域外案例必须检查“明确拒绝”，不能因为无法完成就从用例中删除。

## 用户追加验收

- 一格高差平台：包括凸起平台、上下台阶和抬高的附魔书潜影盒，所有位置都保留可行走路径。
- 容器杂物：原料箱和书箱混入石头、泥土、箭和普通书，机器人只消耗目标原料。
- 背包杂物：放入石头、泥土、普通书、箭及 7 颗私人钻石，验证数量和物品 ID 保持不变。
- 先缺材料，再缺书，最后缺经验，分别核查中文缺口。
- 补货后不发送 good，机器人必须继续等待。
- goodbye 不能恢复任务。
- 玩家发送 good 后重新扫描；仍缺货时再次等待；全部齐备后恢复实际操作。

- 批量与颜色：启动附近放置两个空淡蓝色潜影盒，预期连续交付两套 28 件装备；输出盒颜色必须准确。
- 计数排除：范围内非空淡蓝色盒、范围外空淡蓝色盒不得增加批次；背包中的盒也不计数。
- 原料排除：彩色潜影盒、木桶内放置可用钻石和附魔书，生产后仍保持原状。
- 固定范围：启动 X/Z ±5、Y ±1；移动及 good 补货不改变批次清单。
