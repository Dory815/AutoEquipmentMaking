# 1.3 批量工具

## 功能

版本 `1.3.0`，revision `bulk-tools-20261025`。保留 1.1.0-alpha.2 的寻路、自动疾跑、半成品、缓存修复与取消任务功能。

F6 设置页面分为三个栏目：

| 栏目 | 设置 |
| --- | --- |
| 全局设置 | 工作模式、全部操作快捷键、扫描尺寸、字体倍率、交易、备用铁砧 |
| 新人装备 | 数量模式、手动套数、成品盒 ID、是否使用旧装备制作、可选附魔、鞘翅、盾牌 |
| 批量工具 | 成品盒 ID（默认 `minecraft:yellow_shulker_box`）、制作盒数（1–10）、物品类型 |

旧的设置键和快捷键保持原名。缺少新增设置时使用默认值：新人装备模式、使用旧装备、黄色批量盒、1 盒、精准采集下界合金镐。新人装备仍默认使用淡蓝色盒。两种模式分别保存盒 ID 和数量。设置在任务启动时读取，运行中的任务不随设置页面改动。

每盒批量成品占满 27 格，每格 1 件，全部满耐久、精确附魔。支持：

| 类型 | 附魔 | 名称 |
| --- | --- | --- |
| 精准采集下界合金镐 | 效率 V、精准采集 I、耐久 III、经验修补 I | 挖山镐 |
| 精准采集钻石镐 | 效率 V、精准采集 I、耐久 III、经验修补 I | 挖山镐 |
| 满附魔鞘翅 | 耐久 III、经验修补 I | 不改名 |

每次扫描选定整批空盒。盒不足时进入 `good` 门禁。盒数是成品盒数，每盒独立扫描材料和规划，交付后制作下一盒。装箱和交付均检查全部 27 格，镐同时核对自定义名称。

底材每批最多 6 件，先集中取料，再制作、升级和暂存到成品盒。附魔继续按背包容量分批，预留事务槽位。命名与最后一次铁砧合并同时执行；规划计入 1 级命名费用和 40 级上限。实际服务端菜单必须确认名称、产物和费用后才取出。操作不确定时停止，不重发消耗操作。

新人装备关闭「是否使用旧装备制作」时，不选择原料容器中的下界合金或钻石装备，也不选择附魔钻石。11 件装备底材全部使用钻石和木棍合成，然后升级。弓、盾牌和鞘翅继续从原料或交易取得。开启时保留 1.1 的四条路线：未附魔下界合金、真实砂轮去附魔钻石、普通钻石、新制。批量模式沿用这个复用顺序，钻石镐没有升级步骤。

初始背包保护、原料容器范围、备用铁砧、交易预算、暂停、取消、补货门禁和交付箱绑定沿用现行规则。

## 村民轮换

按精确匹配的附魔书寻找所有候选村民，优先选择当前有货的报价。当前村民缺货后继续其他候选。每个候选均使用实际菜单重新确认。全部候选的匹配报价均缺货时，立即提示冷却，并按真实时间每 20 秒复查。冷却期间不重复提示；恢复时提示一次。不可访问或报价改变的村民不计作「全部冷却」，进入现有复查及 `good` 路径。

本次功能验收完成。独立测试只打开整理后 201 基准的克隆；不直接打开基准，不启动 PCL，不连接 201。

用例与归档脚本：`BulkToolsGameTest`、`tools/run_bulk_tools.ps1`。证据目录：`docs/evidence/v13-bulk-tools-20261025/`。

功能用例在克隆中清空可扫描的原料库存，另置原料箱，并提供原料、未附魔底材、待砂轮去附魔的底材、附魔书和空盒。全部成品经实际制作及附魔菜单产生。此轮不验证用户原物品布局或高处原料盒寻路。村民轮换用例向客户端提供两名测试村民的报价快照，再用实际村民菜单购买；不以此证明 Servux 报价发现或远程网络。

首次新增测试编译因 AABB 参数类型错误失败，仅修正测试参数。`trade-01` 因扫描无关村民后没有安全路线失败。`trade-02` 因测试反复解析 215 MB 历史日志而人工停止。上述结果均不计通过。失败日志保留；后续用例只读取本次任务追加的日志。

四个生产用例合计交付 5 盒、122 件，消耗 1,831 级。两种镐共 54 次真实铁砧命名。四个生产用例均未进入任务暂停、`good` 门禁或任务重开。另一个交易用例完成 4 笔真实采购。
