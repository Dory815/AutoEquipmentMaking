# v1.0 实现与运行说明

本页为 v1.0 历史记录。当前 v1.1 见 [运行与验证](V11_IMPLEMENTATION.md)。用户现行要求所有后续测试只使用独立单人存档。

当前为 `1.0.0-rc.7` 候选版本。它包含真实的制作流程，不是上一阶段的空框架。只有完成游戏内与目标服务器验收后，才称为 v1.0 正式版。

## 使用范围

已实现入口、F8 开始/暂停、F9 急停、本地命令、平台扫描、单附魔目标等级书识别及灵魂疾行、迅捷潜行低等级升级、整盒惩罚分配搜索、钻石合成、下界合金锻造、铁砧合并、成品检查、淡蓝色任务潜影盒回收与批量交付。

使用现有 MiniHUD 0.40.4 / MaLiLib 0.29.3 数据管理器。远程模式要求 Servux 0.11.2 握手成功；单人模式在集成服务器线程读取不可变快照。没有注册第二个 Servux 网络接收器。启动前开启 MiniHUD 的 `entityDataSync`。

灵魂疾行和迅捷潜行允许 I/II/III 原料，优先 III，其次 II+II，再次 II+I+I，最后 I×4。选书后联合规划升级与附魔步骤。其他附魔仍使用目标等级书。仅 I+II 或 I×3 不足以升级至 III。缺货消息显示各等级数量。

启动时背包中的已有物品全部保护。需要至少 16 个空槽，以及一个空快捷栏槽。装备、副手和配置保护槽不会作为原料。原料只从平台内未染色潜影盒（`minecraft:shulker_box`）和普通箱子（`minecraft:chest`）获取。彩色潜影盒、木桶和陷阱箱不作原料容器。基础鞘翅、盾牌、弓为满耐久、无附魔、零铁砧惩罚的成品。

本版候选的配置范围必须在客户端已加载区块内。暂不跨未加载平台区块巡回扫描。支持路径上的平地、普通跳跃和下一级台阶。异常复杂地形停止并报告，不挖方块、不搭桥。工作站和任务盒必须在指定边界及可站立范围内。

## 配置命令

1. 进入工坊后执行 `/aem bind`。
2. 瞄准平台最小角执行 `/aem mark corner1`。
3. 瞄准平台最大角执行 `/aem mark corner2`。
4. 瞄准工作台执行 `/aem mark craft`。
5. 瞄准锻造台执行 `/aem mark smith`。
6. 瞄准铁砧执行 `/aem mark anvil`。
7. 瞄准普通交付箱执行 `/aem mark output`。
8. 在玩家周围摆放空的淡蓝色潜影盒。
9. 关闭菜单，执行 `/aem start`，或按 F8。

`/aem status` 查看状态。`/aem pause` 与 `/aem resume` 控制正常暂停。`/aem cancel` 清除当前动作队列并保留现场物资。

配置保存在游戏目录的 `config/auto-equipment-making/workshop.json`。备用铁砧可以在 `workstations.anvils` 数组中添加。坐标编辑后重启客户端读取配置；选点命令立即更新内存和文件。

铁砧用尽时先查找平台内其他工作铁砧，再重新扫描原料容器中的备用铁砧。优先完好、其次开裂、最后损坏；自动取一件，在配置铁砧工作位的空位置放置后继续。保护物品不消耗，彩色盒和木桶不取料，既有方块不覆盖。库存也耗尽时通知并等待 good。可将铁砧放入合格原料容器，也可直接在平台内补放。普通导航仍不搭桥、不挖路。验证见 [铁砧补位记录](ANVIL_SUPPLY_VALIDATION.md)。

## 批量与容器颜色

启动以玩家脚下所在方块为中心，扫描 X/Z 各 ±5、Y ±1 的 11×11×3 区域（含边界）。只统计已经放置且服务器快照确认 27 格全空的淡蓝色潜影盒。背包中的盒子、非空盒子和范围外盒子不计入。本批数量等于空盒数量；0 个时不消耗原料并结束。

启动后固定盒子清单。机器人依次在原位置装入每盒 14 件装备，挖取、确认拾取，再放入交付箱。补货与移动不重新确定批次数量。每盒开始前检查原料、附魔书、经验及任务盒空状态；剩余盒子缺货时等待 `good`。每盒独立求最低等级费用，不宣称跨多盒混合惩罚书的总费用最优。进度和日志记录本批总数与已交付盒数。

原料搜索仍使用配置的平台边界，与启动时统计盒子的范围分开。统计到的平台外空淡蓝色盒会使启动检查停止，必须扩大平台边界后重新启动。`packing.placement` 和 `/aem mark packing` 仅保留旧配置兼容，不决定生产任务盒的位置。

## 故障处理

缺货时发去重聊天消息并暂停。补充后由任意玩家发送独立聊天消息 `good`；机器人重新检查后继续。缺货等待不接受 F8 或 `/aem resume` 绕过。普通暂停仍用继续命令恢复。菜单身份改变、交互超时或外部槽位操作进入 `RECOVERY_REQUIRED`，不会盲目重发消耗动作。

正常暂停可以继续当前内存队列。掉线、死亡、客户端重启后的中间操作需要人工对账；候选版本尚不提供自动重建整个队列的恢复器。`task.jsonl` 保留动作意图、状态和资产位置。此限制属于正式发布前待验收范围。

玩家移动输入会暂停。其他模组调用原版槽位点击入口时，本模组拦截该次点击并暂停。直接发送自定义网络包的其他模组仍需在目标组合中验证；不能把拦截器视为所有第三方操作的全局锁。

## 验证范围

离线测试使用独立的全配对穷举，对照子集动态规划。覆盖 14 件装备的费用权重、24 组随机初始惩罚、胸甲算例、40 级边界和规划超时。

客户端测试源码位于 `client/src/gametest`，不打进正式模组。测试世界生成原料和工作站；最终装备必须由机器人通过游戏菜单取得。单人测试不证明远程 Servux、代理和 Carpet 附加包兼容性。

用户先前允许独立单人测试。2026-10-23，用户进一步要求配置独立正式服客户端，并确认手动登录后进入 201。独立客户端配置和授权范围见 [正式服客户端说明](FORMAL_CLIENT.md)；工坊配置与远程 Servux 0.11.2 握手通过；生产验收状态见后续验证记录。

## QuickCraft 参考

用户提供 [QuickCraft](https://github.com/qk-yiyihehe/quickcraft) 后，本轮查阅其 README、`QuickCraftMouseCraftAckExecutor` 和 `QuickCraftAnvilPlanner`。借鉴的原则是维护菜单身份、等待权威结果、隔离外部槽位操作。未将参考源码复制到本项目的构建源集中。

远程仓库当前主分支源码使用另一套 Minecraft 命名。它的 26.2 分支 API 查询返回 404，因此没有直接引用该分支的编译兼容性结论。下载的研究副本保存在忽略的 `.reference/quickcraft` 目录，附带原 MIT 许可证，不参与分发。
